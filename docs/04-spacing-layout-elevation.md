# 04 · 间距 · 布局 · 层级

> 空间系统回答三个问题：**放多大**（间距）、**排哪里**（网格/断点）、**谁在上面**（elevation/z-index）。答案必须唯一且可被 AI 确定性执行。

---

## 一、间距刻度（4px 基数）

| Token | px | 用途 |
|---|---|---|
| `--m-space-05` | 2 | 控件内部细节（徽章 py、焦点微调） |
| `--m-space-1` | 4 | 图标与文字间距、紧凑内衬 |
| `--m-space-2` | 8 | 相关元素间 gap（icon+label）、卡片内行距 |
| `--m-space-3` | 12 | 控件内边距（sm 按钮）、列表项 gap |
| `--m-space-4` | 16 | **默认节奏**：卡片内边距、表单字段间、网格 gutter(移动) |
| `--m-space-5` | 20 | lg 按钮内边距 |
| `--m-space-6` | 24 | 卡片分组间、后台 section 间 |
| `--m-space-8` | 32 | 前台卡片组间、后台页面级间距 |
| `--m-space-10/12` | 40/48 | 前台小区块间 |
| `--m-space-16/20/24` | 64/80/96 | 前台大区块间 |
| `--m-space-section` | clamp(48→96) | 前台区块统一节奏（响应式自动） |

**规则**：gap/padding 只出现在这张表里（+组件 token）。8 的倍数优先；4 的倍数兜底；2px 仅控件内部。后台密度更紧：卡片 16px、表格单元格 12px、字段间 16px。

## 二、网格与容器

### 前台

| 项 | 规格 |
|---|---|
| 内容容器 | `max-w: 1280px`（`--m-container-storefront`），gutter 移动 16 / 桌面 24 |
| 窄栏（政策/博客） | `--m-container-narrow` 640px |
| 商品网格（PLP） | 移动 2 列（gutter 8-12）/ 平板 3 列 / 桌面 4 列（服饰类 3 列大图可选） |
| 区块 rhythm | 上下 `--m-space-section`；交替底色用 `bg-band`，同一页面 banding ≤3 次 |
| Hero | 高度自适应内容，禁止 100vh 锁定（移动地址栏跳动）；应用外壳用 `100dvh`（无 dvh 时回落 `100vh`） |

### 后台

| 项 | 规格 |
|---|---|
| 应用框架 | 左侧导航 240px（≤1024 折叠为 56px 图标栏；<768 由全屏抽屉接管；≥1024 可手动收成 64px）+ 顶栏 56px + 内容区 |
| 内容宽度 | 标准 `--m-container-admin` 1000px；窄（表单）640px；宽（数据表）自适应 + 24px 边距 |
| 页面内边距 | 16px（≤768px）/ 20px（默认）/ 32px（>1280px） |
| 卡片栅格 | 仪表盘 KPI：4 列（>1280）/ 2 列（≥768）/ 1 列；卡片间 16px |

### 断点（全系统唯一）

`xs 480 / sm 768 / md 1024 / lg 1280 / xl 1440`。JS 与 CSS 同值。**320px 可用性是底线**（最小测试视口，无横向滚动）。

### 容器查询：组件优先于视口（v1.7）

视口断点只回答"页面怎么排"；**组件长在什么宽度里**由容器查询回答。这条不是技术偏好，是建站场景的必然：商家会把商品卡、信任条、图组塞进任意宽度的区块（半宽、侧栏、弹窗），同一个组件在 1440px 视口里可能只有 320px 宽——视口断点在这里必然判错。

| 宿主 | `container-name` | 触发条件 | 行为 |
|---|---|---|---|
| 商品卡 `.sf-pcard` | `pcard` | ≤160px | quick-add 收为图标态、隐藏 swatch |
| 信任条 `.sf-usp` | `usp` | ≤360px | 条目从纵向堆叠转为横向紧凑排 |
| PDP 主区 `.sf-pdp` | `pdp` | ≤720px | 图组单列、缩略图转横排并置后 |

适用边界：

1. **页面骨架仍用视口断点**（容器宽度由页面决定，用容器查询是循环依赖）。
2. 容器查询只允许做"排列与显隐"，不得改变信息层级（不能在小容器里删掉价格或主 CTA）。
3. 宿主必须显式 `container-type: inline-size`；未声明宿主的 `@container` 规则静默失效，代码评审按缺陷处理。

## 三、Elevation（海拔）

四个阴影层级 + 一条总规则：**静态卡靠底色差与间距分层，阴影只表达浮层高度。**

| 层 | Token | 用途 | 前台 | 后台 |
|---|---|---|---|---|
| 0 | 无 | 静态卡片 | 灰卡/白卡 e0（兜底白卡才用描边） | 白卡 on ink-2，e0 无描边 |
| e1 | `--m-shadow-e1` | 显式浮起卡（`data-surface="elevated"`） | 可选，不得叠在 tinted/filled 上 | hover 提示时才用 |
| e2 | `--m-shadow-e2` | Dropdown / Popover / Combobox 面板 | ✅ | ✅ |
| e3 | `--m-shadow-e3` | 抽屉、模态、命令面板 | ✅ | ✅ |
| e4 | `--m-shadow-e4` | Toast（最高层） | ✅ | ✅ |

深色模式阴影加深（tokens.css 已配对）。**禁止**用阴影表达"品牌感"——无描边的 `tinted`/`filled` 卡不得再叠 e1，否则就是"底色差 + 弱阴影"的双弱信号；e1 只给显式 `elevated` 或后台 hover 提示。

### 3.1 玻璃材质（v1.7 · 仅限 chrome 与 overlay）

玻璃只解决一个问题：**固定/浮动面板下方的内容仍需被感知**（吸顶导航、购物车抽屉、命令面板）。它是层高语言的一部分，不是装饰语言。

| Token | 值 | 用途 |
|---|---|---|
| `--m-glass-blur` | 20px | 背景模糊半径 |
| `--m-glass-alpha` | 72% | 面板底色不透明度（`color-mix` 到 transparent） |
| `--m-glass-dim` | 浅色 `rgb(15 18 24 / .08)` / 深色 `rgb(255 255 255 / .10)` | 内描边调暗层（`inset 0 -1px 0`），补 1px 边界 |

**硬禁止：内容卡与商品图禁用玻璃。** 理由：商品图的颜色准确性是电商的转化前提，模糊/透色会直接改变商品观感；内容卡是阅读面，透出背景会破坏对比度契约（§02 §六）。Apple HIG 对 liquid glass 的适用面同样限定在固定/浮动面板与分隔线，并要求配调暗层——这不是审美取舍，是可读性底线。

配套要求：

1. **必须有不支持时的实底回退**：`@supports not ((backdrop-filter: blur(1px)) or (-webkit-backdrop-filter: blur(1px)))` → 纯色 `--m-bg-chrome` + 常规底边线。
2. **尊重系统降透明**：`@media (prefers-reduced-transparency: reduce)` → 去掉 blur 与透明，回到实底。
3. **边界不能只靠模糊**：玻璃面板必须同时有 `--m-glass-dim` 内描边或实底阴影（e2+），否则在浅色内容上会"融化"。
4. 消费点（v1.7 唯一）：`.sf-header.is-stuck`。新增消费点必须同批补回退与降透明两条 `@media`。

## 四、Z-index 阶梯（封闭枚举）

```
raised  10   局部悬浮（sticky 表头、卡片内浮层）
nav     100  顶栏/侧栏
drawer  300  购物车抽屉、筛选抽屉
modal   400  模态、命令面板（⌘K）
toast   500  通知
tooltip 600  气泡（永远最上）
```

嵌套规则：模态内只允许 tooltip（600）与自身的 toast。抽屉上开模态 = modal(400) > drawer(300) 自动成立。**自造数值 = 校验失败。**

## 五、圆角

主旋钮 `--m-radius: 8px`，派生：xs 2 / sm 4 / **md 8（控件、输入框、按钮）** / **lg 12（后台卡片）** / **xl 16（前台卡片、媒体、模态）** / 2xl 24（仅全屏 Sheet / 营销大卡）/ pill（徽章、swatch）。

组合规则：嵌套时内层 ≤ 外层（卡片 16 内的按钮 8 ✓）；媒体图与所在容器同角或内缩（图片 12 在卡片 16 内 ✓）。品牌可在 Brand Kit 改 `--m-radius`（6→12 整套缩放，shadcn 旋钮法）。`xs` 用 `max(2px, …)` 保底，6px 旋钮下不会产出 1.5px 的非网格值。

**语境门（v1.7 · R07 强制）**：`xs` 合法，但**用在哪里**有约束。

| 语境 | 允许档位 | 说明 |
|---|---|---|
| 前台商品图 / 卡媒体（`.sf-gallery__main`、`.sf-hero__figure`、`.sf-mediaband`、`.sf-editorial__media`、`.sf-post`、`.sf-prose figure`、`.m-product-card`） | **≥ `lg`（12px）** | 大幅媒体用小圆角会显"廉价截图感"，且与卡片容器角不匹配 |
| 小缩略图（如 `.sf-gallery__thumb`） | `sm` 起 | 尺寸小、圆角必须随之收缩，不参与上一条 |
| 图表柱条 / 微元素 | `xs` 允许 | 2px 是数据标记的常见处理 |
| 其余控件与卡片 | 按菜单值 | 不得自造数值 |

实现：`ai/checks/r07-radius.mjs` 在"是否取自 token"之外增加语境判定——token 值也要过语境门。这条补的是"菜单合规但配比失衡"：全仓 `radius-xs` 用了 63 次而 `md/lg/xl` 只有 13 次，单看每一条都合规。

## 六、焦点环（双规格）

| 舞台 | 规格 |
|---|---|
| 前台 | 外环：`outline: 2px solid border-focus` + `outline-offset: 2px`（环落在页面底，保持 `border-focus`） |
| 后台 | 内嵌环（Polaris 式）：`outline: 2px solid border-focus` + `outline-offset: -3px`（贴边框内侧，不挤占布局） |
| 实底按钮 | **仅后台内嵌环**改取该变体的 `*-fg`（`--m-primary-fg` / `--m-critical-solid-fg`），因为环压在控件填充上；**前台外环不得改用 `*-fg`**——白环白底实测 1.00:1、深环深底 1.22:1（v1.4 修正） |
| Checkbox / Radio / Switch | 环永远画在可见部件外侧（offset 为正），因此无论选中与否都保持 `border-focus`，不得改用 `*-fg` |

颜色基准是 `--m-border-focus`（对任意 surface ≈5.8:1，WCAG 1.4.11）；但**内嵌环压在控件填充上时，必须按填充重新校准**——info-9 对 brand-9 只有 1.11:1，这就是后台实底变体单独换环色的原因。**永远 `:focus-visible`**，鼠标点击不出现环。实现在 `ai/tokens.css` 的全局唯一声明点（outline，非 box-shadow）；组件层只允许在 `.stage-admin` 作用域内覆盖实底变体的 `outline-color`，禁止移除 outline。

## 七、触达尺寸

| 场景 | 最小 |
|---|---|
| 任何可点元素（WCAG 2.5.8） | 24×24px |
| 移动端主 CTA / 行内可点项 / 表单控件 | 44×44px（输入框移动端高 44、字号 16px，见 tokens.css 移动端块） |
| 相邻触达目标间距 | 达标目标（≥24px）可 4px 并列；未达标目标或移动端主操作之间 ≥8px |
| Swatch / 数量步进器 / Switch | 视觉 20–24px + 热区扩展至 44px |

> **toolbar 例外**：工具族（`.m-tool`）是 32px 目标，满足 24px 底线，因此允许 4px 并列间距（`--m-tool-gap`）。这是“8px 规则”的唯一合法例外，不要照搬到移动端主操作。
