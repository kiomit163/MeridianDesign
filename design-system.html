十条设计原则

01 Opinionated by default每个场景只有一个推荐组件。选择越少，系统越一致，AI 越不跑偏。
02 Semantic over literal写 bg-surface，永不写 #FFFFFF。换主题换品牌零改动。
03 Content is the interface文案与像素同等地位：错误必须说怎么修，Toast ≤3 词。
04 One spine, two stages前台卖（spacious/expressive），后台运营（dense/productive），共享一条脊骨。
05 Trust is a material价格透明、真实评价、真实库存、对等拒绝权 —— 信任是转化函数。
06 Accessible is the floorWCAG 2.2 AA + 欧盟 EAA 烧进 token 与组件，不靠事后审计。
07 Machine-legibleAI 无法确定性执行的规则不是规则。validate.mjs 拦截违规。
08 Performance is designLCP≤2.5s / INP≤200ms / CLS≤0.1 是设计约束。
09 Motion with restrainthover 150ms、入场 300ms、前台上限 600ms、reduced-motion 一票否决。
10 Density is a dial后台 comfortable/productive 两档，切换靠 token 不靠重写。

表面层级（Surface Ranks）与两种拓扑

背景是有序阶梯不是颜色集合。浅色下越亮 = 越靠前（内容），越暗 = 越后退（结构）；深色数值反向但语义指向不变。点左上角切「后台」可看 chrome 阶梯生效。

surface-ranks四级阶梯（实时值，随主题变化）
inset −2 凹槽 chrome −1 框架 surface 0 台面 overlay +1 浮层

口诀：用户的眼睛停在哪里，哪里就是 rank 0。框架内 hover 必须换梯度（chrome-hover）——因为 surface-hover 与 chrome 同值，直接用会完全不可见。

topologyA 画布+卡片 / B 框架+台面
A · 记录型页面（灰底白卡）—— 订单/商品/设置/仪表盘
B · 外壳型（灰框架 + 白台面）—— IDE/对话/邮件/CRM
work surface

判据："内容是一块块可数的卡片 → A；一整片连续的流（对话/文档/代码）→ B"。把 A 强加给外壳 = 层级颠倒（框架与台面同灰，作者再靠直觉改白 → 出现"两个侧栏一灰一白"）。

state-layerhover 8% · pressed 12% · selected 10%

实底组件用显式 token：浅色主题 hover 变深（9→10），深色主题 hover 变浅（9→8）。方向规则写死。

Foundations · Motion

动效：双人格系统

后台 Productive（100-300ms 快而克制），前台 Expressive（200-600ms 有空间叙事）。点击任意曲线重放动画。系统对 prefers-reduced-motion 全局降级。

duration × easing点击重放 · 标准 / 入场 / 退场
150ms standard
200ms standard
300ms enter
450ms enter（前台）
300ms exit
600ms 前台上限
缓动：standard cubic-bezier(0.2,0,0,1) · enter (0.05,0.7,0.1,1) · exit (0.3,0,0.8,0.15)。入场永远比退场慢 —— 用户等着走。只动 transform/opacity。
